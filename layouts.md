That is 155 training scenarios and 199 held-out scenarios, 354 in total. Every free cell in every layout can reach the goal, and none is enclosed (every cell has at least one safe action).

## Why these held-out maps
- **`clutter`**: the team has reserved it as the held-out map since the first 10×10 runs, and no saved run has evaluated on it. Its goal and difficulty are similar to the training maps, so it is the cleanest test of an unseen *obstacle arrangement*.
- **`pillars`** (new): regular blocks with the **goal at the top right**. It has short paths, so failure here mainly means the policy did not learn to read the goal from the map observation.
- **`spiral`** (new): a single long corridor to a **central goal**. Paths are about 3× longer than on the training maps, so it is deliberately the hardest map. Report it separately: a failure here mixes unfamiliarity with difficulty and should not be pooled into a single "held-out" number without saying so.

## Leakage check
On 2026-11-22 I scanned all 40 training summaries under `results/`:
- 26 use the 6×6 map.
- 6 use custom 10×10 maps (`configs/integration_10x10.json`).
- 8 use `train_layouts = [rooms, zigzag]`.

**None trained on `clutter`, `spiral` or `pillars`.** The 10×10 diagnostic scripts (`run_10x10_*.py`) hard-code `("rooms", "zigzag")` and never evaluate `clutter`. `spiral` and `pillars` did not exist before this change.

## Scenario protocol
- There is one scenario per reachable, non-goal free cell. Each has an `id` of the form `<layout>-<row>-<col>`, a `split`, a `start`, a `marked_start` flag (true for the `S` cells in the map) and a `shortest_path`.
- Each scenario is evaluated as one episode with a forced start, the **shield off**, greedy argmax (no exploration), `max_steps = 100` and map observations (104 inputs). The environment and policy are deterministic, so repeating a scenario adds nothing. `seed` is recorded only as metadata.
- Report results on all reachable starts, and separately on `marked_start == 1` only, where it helps comparison with the training-time start set.

## Commands (for every method's checkpoint)
```bash
python evaluate.py --model <checkpoint.pt> --scenarios evaluation_scenarios.json --split train   --output results/eval/<method>_seed<k>_train.csv
python evaluate.py --model <checkpoint.pt> --scenarios evaluation_scenarios.json --split heldout --output results/eval/<method>_seed<k>_heldout.csv
python make_eval_scenarios.py --check   # confirms the scenario file is unchanged
```
Each output row has `scenario_id, split, layout, start, marked_start, shortest_path, reward, steps, success, collision, timeout, unsafe_proposals, interventions`. The printed summary breaks results down by split and by layout.

**Training rule for final runs:** `--size 10 --observation-mode map --train-layouts rooms zigzag`. Never pass a held-out layout to `train.py`. Run the held-out split only on final, frozen checkpoints.
